# Задание на день 3. Проектирование и разработка ядра приложения «Заметки»

**Проект:** мобильное приложение «Заметки»  
**Срок:** конец дня 3  
**Основание:** функциональные требования проекта — создание, просмотр, редактирование и удаление заметок, локальное хранение, поиск и экспорт в файл.

## Цель дня

Спроектировать архитектуру приложения, определить модель данных и контракты модулей, описать взаимодействие компонентов, подготовить тест-кейсы и выполнить первичную проверку основных сценариев.

## Что сделать по ролям

| Роль | Задача | Файлы / результат |
|---|---|---|
| Руководитель проекта | Сформировать задание дня, проверить комплектность документации и согласовать результат | `docs/day3/Задание_день3.md`, `README.md` |
| Аналитик | Описать архитектуру, модель `Note`, контракты методов и диаграммы последовательности | `docs/day3/architecture.md`, `docs/day3/sequence-scenarios.md` |
| Разработчик | Подготовить модель заметки и бизнес-логику создания, просмотра, изменения, удаления, поиска и экспорта | `src/core/` |
| Тестировщик | Подготовить тест-кейсы, провести ручную проверку, фиксировать дефекты | `docs/day3/test_cases.md`, `manual_check.md`, `bugs.md`, `tests/` |

## Функциональные требования

| ID | Функция | Описание |
|---|---|---|
| M1 | Создание заметки | Пользователь вводит заголовок и текст, затем сохраняет заметку |
| M2 | Просмотр заметок | Пользователь видит список заметок и может открыть отдельную заметку |
| M3 | Редактирование | Пользователь изменяет заголовок и содержимое существующей заметки |
| M4 | Удаление | Пользователь удаляет заметку с подтверждением действия |
| M5 | Локальное хранение | Заметки сохраняются на устройстве и доступны после перезапуска |
| M6 | Поиск | Поиск выполняется по заголовку и содержимому без учёта регистра |
| M7 | Экспорт | Пользователь сохраняет выбранную заметку в файл TXT с кодировкой UTF-8 |

## Критерии завершения дня

- Описана архитектура приложения и определены основные компоненты.
- Определена модель `Note` и контракты операций.
- Подготовлены диаграммы последовательности для создания, редактирования/удаления, поиска и экспорта.
- Подготовлены тест-кейсы для всех основных функций.
- Описан порядок ручной проверки и форма регистрации дефектов.
- Документация согласована и сохранена в репозитории.

## Не входит в день 3

Полная реализация экранов приложения, окончательная интеграция с платформенными API, публикация приложения и облачная синхронизация. Реализация локального хранилища и интерфейса может выполняться в последующие дни практики согласно общему плану.

## Порядок работы с Git

1. Создать рабочие ветки от согласованной ветки проекта.
2. Каждый участник изменяет файлы в рамках своей роли.
3. Создать Pull Request в общую рабочую ветку.
4. Проверить документацию, тест-кейсы и результаты ручной проверки.
5. После проверки объединить изменения в основную ветку.
